# 流量推文方法论（播客 → 高流量推文）

核心逻辑：**流量 = 算法信号 × 人性钩子**。算法侧决定分发量（回复权重、停留时长、负反馈惩罚），人性侧决定点击与互动（好奇缺口、高唤起情绪、具体数字）。每条稿子两侧都要过一遍。

## 工作流

```
拆信息 → 选角度 → 写钩子（≥3 候选）→ 成稿 → 自检 → 展示/复盘建议
```

输入是一批播客文档（转写稿/文章，路径通常在 `dump/transcripts/`、`dump/articles/`）。>10 篇时用 subagent 并行拆素材（每批 ≤10 个，只返回素材清单+出处），汇总后统一进入选角度。

## 第一步：拆信息

通读后产出素材清单，每条注明：**内容 + 出处（哪篇第几段）+ 目标人群 + 情绪唤起类型**。

按流量价值排序取材：

| 优先级 | 素材类型 | 为什么有流量 |
| --- | --- | --- |
| 1 | 反常识观点 | 打破预期 → 评论区分歧 → 回复权重最高 |
| 2 | 惊人数字/对比 | 具体数字可信且易转发；对比自带故事 |
| 3 | 高唤起情绪点（焦虑/惊叹/不甘） | 高唤起情绪驱动转发，低唤起（平静/惋惜）不会 |
| 4 | 可独立引用的金句 | ≤140 字自成一体，是转发的最小单位 |
| 5 | 故事/案例 | 叙事比说教停留时间长 |

**要求忠于原文、可回溯**：金句和数字必须能在原文找到，不虚构、不夸大倍数。个人感受/号召部分是写作者视角，可自由发挥。

## 第二步：选角度（同一素材至少找 2 个角度）

- **反常识 × 与读者相关 = 最优角度**：既有争议（评论吵起来）又有代入感（觉得在说自己）
- 把"播客里的话"翻译成"读者的处境"：原文讲复利定律 → 读者角度是"为什么你比同龄人差的那点差距 5 年后追不上"
- 争议要有事实托底：靠原文的真实观点制造分歧，不靠歪曲原意引战（负反馈是账号级的，见下）

## 第三步：写钩子（流量生死线）

信息流里推文被折叠，**读者只看到前 1-2 行**——钩子必须独立成立、留好奇缺口。钩子决定 80% 的打开率，所以**先写 ≥3 个候选钩子再选优**，禁止想一个写一个。

钩子库（每个公式含示例和适用场景）→ **读 `references/traffic-playbook.md` 的「钩子库」一节**后再动笔。

硬规则：
- 钩子里不说完结论——点开才有停留时长，说完了就没有然后了
- 钩子与正文一致——标题党换来的点击会以 mute/block 的形式还回来，且惩罚整个账号

## 第四步：成稿

- **单推**：钩子（1-2 行）→ 论据/故事（具体数字）→ 可转发金句 → 互动点
- **thread**：钩子推 → 每推一个论点（首行自带小钩子让人继续翻）→ 收束 → 唯一 CTA
- 每条 ≤280 字符，写完用 `wc -m` 逐条验证；中文单推 120–140 字更佳（留转发时加评论的余地）
- 外链放自回复，不进正文（算法对外链降权）
- 结尾互动点要"值得回复"：一个可站队的问题、一个开放争议——回复是权重最高的信号，"求转发/求关注"式的 engagement bait 反被降权

## 发布自检清单

- [ ] 前 2 行折叠后独立成立，且给了点开的理由（好奇缺口/利益点）
- [ ] 每条 ≤280 字符（`wc -m` 验证过）
- [ ] ≥1 个具体数字/细节，≥1 句可独立转发的金句
- [ ] 结尾有明确互动理由，且不是 engagement bait
- [ ] 素材忠于原文可回溯（金句、数字可指回出处）
- [ ] 外链（若有）已放自回复

## 产出格式（每篇/每主题）

1. 素材清单（含出处）
2. ≥3 个候选钩子（标注钩子类型）+ 选型理由
3. 成稿：单推 ×2（不同角度）+ thread ×1（5-8 条）
4. 每条注明：形式 / 钩子类型 / 字符数 / 素材出处

先在会话中直接展示全部内容供挑选；确认后存 `dump/tweets/<主题>/`（批量时附 INDEX.md）。

发布后复盘看漏斗：**曝光 → 互动率 → 主页点击/涨粉**。打开率差 → 换钩子类型再测；互动率差 → 加强结尾争议点或内容密度；涨粉差 → 加强身份标签（让人知道"这个号讲什么"）。

算法机制速查与反模式清单见 `references/traffic-playbook.md`。
