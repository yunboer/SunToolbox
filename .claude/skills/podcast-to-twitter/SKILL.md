# 播客 → 推特稿

## 两种模式

- **单篇提炼**（输入为 1 篇文档）：提炼该篇的多个发布角度
- **主题聚合**（输入为多篇/目录）：跨篇观点串成主题 thread

输入 >10 篇时：用 subagent 并行提炼（每批 ≤10 个，每个 subagent 负责若干篇，只返回素材清单：反常识观点/金句/数据/故事，附出处），汇总后统一写稿 —— 不要自己串行读完全部。

## 素材优先级

反常识观点 > 金句 > 数据点 > 故事案例。先列素材清单，再挑选写稿。

## 写作规范

### 核心原则：真实研究者的个人分享（不是机械总结）

必须以"我"的视角讲述研究与感受，把读者拉进情境 —— 禁止媒体式客观罗列观点。

**开头必须制造代入感，且必须简短**（自媒体式：2–4 行内完成钩子，不铺垫）：
- **排比叩问（首选）**：连续 2–3 个"你是不是……"直击痛点层层递进，一句话转折引入。标杆示例：
  > 你是不是还在为每天 996 感到前途渺茫？你是不是正经历人生的挣扎时刻？你是不是也梦想着有一天财富自由？那你该听听，"孙割"在 2016 年是怎么讲的。
- 反差自白："我一直叫他孙割，直到听完他 2016 年的播客"
- 场景引入："凌晨改 PPT 的时候，我突然听懂了这句话"

**叙事骨架**（要素齐全，顺序可调）：
1. 代入感开头（拉读者进情境）
2. 个人行为：最近研究了xx / 听完 154 期 / 翻出 2016 年的节目（具体数字增可信）
3. 承认争议与梗：先自嘲拉近距离（"虽然大家都叫他孙割"）—— 真实感来自矛盾态度
4. 时间反差：xx 年前的话 → 现在更适用（"清醒得可怕"）
5. 具体金句 + 个人感受（"这句我反复想了好几天"，情感要具体，不写"深受启发"这类空话）
6. 联系当下环境与读者（"对现在的年轻人"）
7. 真诚号召（"建议每个xx都去细品"）

**风格参考**（用户示例，此风格的标杆）：
> 最近研究了孙哥的xxx播客，真心推荐每一个有梦想的年轻人仔细研究孙学。虽然大家都称呼孙宇晨为孙割，但是孙哥早在xx年前说的话就让人感到可怕的清醒。尤其适用于现在的社会环境，对于现在的年轻人，建议每个人都去细品孙哥的语录。

**真实感要点**：
- 允许矛盾态度（"我不喜欢他这个人，但这些话真清醒"）—— 真实的人就是矛盾的
- 网络梗自然使用（孙割/孙学/细品），不堆砌
- 短句、口语化、适度 emoji、hashtag ≤2 个

### 技术规范

- **长度**：单推 ≤280 字符（写完用 `wc -m` 验证每条）；中文单推 120–140 字更佳
- **thread**：5–10 条；第 1 条代入感钩子，中间每条一个论点（金句+感受），最后一条收束/号召
- **双语**：中文为主稿；英文版按英文推特习惯重写（不是直译），争议人物在英文语境有对应表达（如 Justin Sun 的 crypto 争议）
- **第三人称转述版**：标注出处（"孙宇晨认为：……"），仅用于引用/讨论场景的备选
- **忠实**：金句必须忠于原文可回溯，不虚构；个人感受部分是写作者视角可以自由发挥

## 每篇/每主题的标准产出（8 条左右，按推荐度排序）

1. ⭐ 中文第一人称 thread（主力稿）
2. 中文第一人称单推 ×2–3（不同角度）
3. 英文第一人称 thread ×1
4. 英文第一人称单推 ×1
5. 第三人称转述单推 ×1（中或英）

每条稿子注明：形式 / 口吻 / 字符数 / 素材来源（哪篇的什么观点）。

## 输出与归档

- 先在会话中直接展示全部稿子供用户挑选
- 归档位置按以下优先级确定（不要写死任何机器特定路径）：
  1. 用户当场指定的位置（最优先）
  2. `.env` 中的 `HERMESNOTE_DIR`（笔记库/归档根目录，见 `.env.example`）：
     存入对应主题子目录；无既有目录时在根下按主题新建（如 `<主题>/tweets/`）
  3. 未配置且用户未指定时询问一次；用户不指定则存 `dump/tweets/<主题>/`
- 文件为 Markdown，批量产出时附 INDEX.md；归档目录若是 git 仓库则按其工作流 commit + push，否则仅保存
