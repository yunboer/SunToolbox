# 播客 → 推特稿

## 两种模式

- **单篇提炼**（输入为 1 篇文档）：提炼该篇的多个发布角度
- **主题聚合**（输入为多篇/目录）：跨篇观点串成主题 thread

输入 >10 篇时：用 subagent 并行提炼（每批 ≤10 个，每个 subagent 负责若干篇，只返回素材清单：反常识观点/金句/数据/故事，附出处），汇总后统一写稿 —— 不要自己串行读完全部。

## 素材优先级

反常识观点 > 金句 > 数据点 > 故事案例。先列素材清单，再挑选写稿。

## 写作规范

- **长度**：单推 ≤280 字符（写完用 `wc -m` 验证每条）；中文单推实际控制在 120–140 字更佳
- **thread**：5–10 条；第 1 条必须是钩子（悬念/反常识/利益点），中间每条一个论点，最后一条收束或 CTA
- **风格**：短句、观点先行、口语化、适度 emoji、hashtag ≤2 个、不堆砌
- **双语**：中文为主稿；英文版按英文推特习惯重写（不是直译），保持同一论点结构
- **口吻**：
  - 第一人称（主力）：无主语观点句，像发推人自己的观点（如"婚姻的本质是经济联盟，不是爱情"）
  - 第三人称转述：标注观点出处（如"孙宇晨认为：……"），用于引用/讨论场景
- **忠实**：忠于原文观点，不虚构；金句可直接引用并注明出处

## 每篇/每主题的标准产出（8 条左右，按推荐度排序）

1. ⭐ 中文第一人称 thread（主力稿）
2. 中文第一人称单推 ×2–3（不同角度）
3. 英文第一人称 thread ×1
4. 英文第一人称单推 ×1
5. 第三人称转述单推 ×1（中或英）

每条稿子注明：形式 / 口吻 / 字符数 / 素材来源（哪篇的什么观点）。

## 输出与归档

- 先在会话中直接展示全部稿子供用户挑选
- 归档遵循全局规则（~/.claude/CLAUDE.md）：存入 `/Users/sunyuxiang/Documents/hermesnote`
  对应主题目录（源文档若无既有目录，可在 hermesnote 根下按主题新建，如 `justinsun研究/tweets/`）
- 文件为 Markdown，批量产出时附 INDEX.md；存入后 commit + push hermesnote
- 用户指定输出位置时以用户为准
