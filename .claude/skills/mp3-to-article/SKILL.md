# MP3 → 文章

两阶段流水线：**转写**（脚本，多文件并行）→ **润色成文**（subagent，多任务并行）。
输出语言与音频语言一致（只润色，不翻译）。

## 阶段 1：转写

对每个音频文件执行（多个文件时用后台任务并行跑）：

```bash
python3 .claude/skills/mp3-to-article/scripts/transcribe.py <音频文件> -o dump/transcripts/<名称>.txt
```

- 默认后端 `glm`（GLM-ASR-2512），需仓库根 `.env` 配置 `GLM_API_KEY`
- 脚本自动切片处理 API 的 30 秒限制并链式传递上下文，无需干预
- `--backend mlx` 为 Mac 本地方案预留（尚未实现）
- 单个文件内串行转写（保上下文连贯），**文件之间必须并行调度**

## 阶段 2：subagent 润色成文

每个转写稿派一个 subagent（Agent 工具，并行派发），指令要点：

- 通读全文，输出**原语言**的结构化文章（不翻译）
- 去除口语填充词（嗯、呃、就是说、这个那个）和重复表述
- 忠于原意：不新增观点，不删减有信息量的内容
- 修正明显的转写错误（同音字、专有名词，结合上下文判断）
- 组织结构：起一个贴切标题，合理使用小标题分节、分段
- 输出 Markdown，写入 `dump/articles/<名称>.md`（用户指定目录时以用户为准）

## 输出与收尾

- 中间产物（转写稿）在 `dump/transcripts/`，成品文章在 `dump/articles/`，均在 dump/ 下不提交
- 完成后向用户报告每个文件的文章路径和字数
